# Пуши и Edge Functions — что настроить руками

Документ описывает разовую настройку, без которой уведомления и оплата
не работают. Проверено 19.09.2026: в живой базе `device_tokens` — **0 строк**
за всё время, задеплоенных Edge Functions — **ни одной**, при том что
`price_drops` уже накопила 8 записей. То есть повод отправить пуш был
восемь раз, а отправлять было некому и нечем.

Всё, что в этом файле, делается в твоих аккаунтах — Firebase, Apple
Developer, Supabase. Моя часть (код, CI, деплой) идёт после и описана
в конце.

---

## Почему сейчас не работает

**Пуши.** В репозитории нет ни `google-services.json`, ни
`GoogleService-Info.plist`, ни `lib/firebase_options.dart`, и ни один
CI-скрипт их не создаёт. Папки `android/` и `ios/` в git не хранятся
(см. CLAUDE.md §6.4) — они генерируются заново при каждой сборке, поэтому
положить туда файлы «один раз руками» нельзя.

Из-за этого `Firebase.initializeApp()` в `lib/main.dart:101` падает всегда.
Падение поймано в `try/catch` и уходит в лог строкой «Firebase не настроен —
пуши отключены». Дальше `PushService.init()` не выполняется, флаг `_ready`
остаётся `false`, и `syncToken()` выходит первой же строкой — токен
устройства в базу не попадает. Ошибки на экране при этом нет: приложение
ведёт себя так, будто пуши просто никому не нужны.

На iOS есть и вторая стена: в `codemagic.yaml` в `Runner.entitlements`
прописан только `com.apple.developer.applesignin`. Без `aps-environment`
система вообще не выдаёт APNs-токен.

**Оплата.** Идёт через Edge Function `create-payment`, а функции не
задеплоены ни одной. В таблице `payments` ноль строк — сходится.

## Часть 1. Firebase

### 1.1. Проект и два приложения

Проект — **`komplekt-8847a`** (имя «Komplekt»), Sender ID `1002346937741`.

**Android — сделано 19.09.2026.** Приложение «Комплект Android»,
package `kz.komplekt.app`, App ID
`1:1002346937741:android:3e50c6ff9480a07a1b91c4`. Значения перенесены
в `lib/firebase_options.dart` — скачивать `google-services.json` не
понадобилось, конфиг собран руками (почему именно так — в комментарии
в самом файле).

**iOS — тоже сделано 19.09.2026.** Приложение «Комплект iOS», Bundle ID
`kz.komplekt.app`, App ID `1:1002346937741:ios:a24c2615d302d9f91b91c4`.
Значения тоже в `lib/firebase_options.dart`.

Но на iOS одного этого мало: осталось 1.2–1.4 (APNs-ключ, загрузка его
в Firebase, возможность Push у App ID) плюс флаг `PUSH_READY`. Без них
система не выдаст токен, и строка состояния в профиле это покажет.

> Про Android важно: сейчас `flutter create .` генерирует пакет по
> умолчанию — `com.example.komplekt`. Я добавлю в `ci.yaml` шаг, который
> принудительно ставит `kz.komplekt.app`, тем же приёмом, каким
> `codemagic.yaml` уже фиксирует Bundle ID для iOS. Так идентификатор
> будет один на обеих платформах. Заодно это снимает отдельную проблему:
> с пакетом `com.example.*` приложение в принципе нельзя опубликовать
> в Google Play.

**Оба файла пришли мне** — из них я соберу `lib/firebase_options.dart`.
Это не секреты: те же значения лежат внутри любого установленного
приложения, Google так их и задумывал. Настоящий секрет будет в п. 1.4,
его мне присылать не надо.

### 1.2. APNs-ключ в Apple Developer

Apple Developer → Certificates, Identifiers & Profiles → Keys → «+»:
- имя любое, например `komplekt-apns`
- галочка **Apple Push Notifications service (APNs)**
- скачать `.p8` (он даётся **один раз**, повторно не скачать)
- записать **Key ID** и **Team ID**

### 1.3. Загрузить APNs-ключ в Firebase

Firebase Console → Project settings → **Cloud Messaging** → раздел iOS →
APNs Authentication Key → Upload: файл `.p8`, Key ID, Team ID.

Без этого шага пуши на iPhone не придут, даже если всё остальное
настроено правильно.

### 1.4. Включить Push Notifications у App ID

Apple Developer → Identifiers → `kz.komplekt.app` → включить
**Push Notifications** → Save.

Профиль подписи Codemagic создаёт сам (`fetch-signing-files --create`),
но возможность должна быть включена у самого App ID, иначе профиль
выпустится без неё.

**Это блокирующий шаг, и он ломает сборку раньше всего остального.**
Проверено на сборке 26 (19.09.2026): с `aps-environment` в entitlements
и выключенной возможностью у App ID сборка падает на подписи —

```
Provisioning profile "Komplekt ios_app_store ..." doesn't include
the aps-environment entitlement.
```

Поэтому `aps-environment` и `UIBackgroundModes` в `codemagic.yaml`
спрятаны под флаг. После включения возможности здесь — задать в Codemagic
→ App settings → Environment variables, группа **supabase**:

```
PUSH_READY = 1
```

Порядок строгий: сначала возможность у App ID, потом флаг, потом сборка.
Без флага сборка идёт как обычно, просто пуши на iOS не работают.

### 1.5. Сервисный аккаунт для отправки (это секрет)

Firebase Console → Project settings → **Service accounts** →
Generate new private key → скачается JSON.

**Этот файл мне не присылай.** Из него понадобятся три значения, и
вставишь ты их сам в Supabase на следующем шаге:

| Из JSON | Куда |
|---|---|
| `project_id` | `FCM_PROJECT_ID` |
| `client_email` | `FCM_CLIENT_EMAIL` |
| `private_key` | `FCM_PRIVATE_KEY` |

`private_key` — длинная строка с `-----BEGIN PRIVATE KEY-----`. Копировать
целиком, как есть; функция сама приводит `\n` к переводам строк
(`send-price-alerts/index.ts:19`).

## Часть 2. Supabase

### 2.1. Секреты Edge Functions

Dashboard → Edge Functions → **Secrets**. Добавить:

Для пушей:
- `FCM_PROJECT_ID`
- `FCM_CLIENT_EMAIL`
- `FCM_PRIVATE_KEY`

Для оплаты:
- `CLOUDPAYMENTS_PUBLIC_ID`
- `CLOUDPAYMENTS_API_SECRET`

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам,
их заводить не надо.

### 2.2. Database Webhook на снижение цены

Dashboard → Database → **Webhooks** → Create:
- таблица `public.price_drops`
- событие **Insert**
- тип **Supabase Edge Functions**, функция `send-price-alerts`
- метод POST

Делается **после** деплоя функции (п. 3), иначе в списке её не будет.

### 2.3. Тариф

Организация на FREE (CLAUDE.md §10.3). Проект уже дважды вставал, и
автопауза после 7 дней без обращений к API никуда не делась. На
поставленном на паузу проекте не сработают ни вебхуки, ни функции —
пуши замолчат ровно так же, как сейчас, но по другой причине. Если
уведомления должны быть надёжными, тариф придётся поднимать:
Supabase → Settings → Subscription.

- **`codemagic.yaml`** — `aps-environment` в `Runner.entitlements`
  и `UIBackgroundModes: remote-notification` в `Info.plist`, **под флагом

- **Строка состояния пушей** в листе «Настройки уведомлений» в профиле.
  Показывает первую несработавшую ступень цепочки: нет Firebase → нет
  разрешения → нет токена → токен не записан в базу. Без неё проверить
  результат настройки будет нечем: все ошибки в `PushService` гасятся
  в `try/catch` и уходят в `debugPrint`, которого на телефоне не видно.
  Именно поэтому поломку не замечали с первого релиза.

- **`lib/firebase_options.dart`** — настройки Android (19.09.2026).
  iOS бросает понятную ошибку, пока приложение не заведено в Firebase.
- **`lib/main.dart`** — `Firebase.initializeApp(options:
  DefaultFirebaseOptions.currentPlatform)` вместо вызова без параметров.
  Именно из-за вызова без параметров инициализация падала всегда.
