# КОМПЛЕКТ — инструкция «с нуля», без программирования

Это пошаговое руководство для человека, который не программирует. Читай по
порядку. Если где-то застрянешь — пришли мне скриншот или текст ошибки, помогу.

---

## 1. Что у тебя вообще есть

В папке проекта лежит **исходный код мобильного приложения** «КОМПЛЕКТ» —
маркетплейс отделочных материалов. Это ещё не готовый файл для установки, а
«чертежи», из которых собирается приложение.

Карта папки простыми словами:

- `lib/` — сам код приложения (экраны, кнопки, логика). Трогать не нужно.
- `supabase/` — настройки «облака»: база данных и сервер. Понадобится, когда
  захочешь настоящую версию (с регистрацией и сохранением данных).
- `pubspec.yaml` — список «деталей» (библиотек), из которых собирается приложение.
- `.env.example` — шаблон файла с ключами доступа.
- `.github/` — рецепт автоматической сборки приложения в облаке (см. Путь А).
- `README.md`, `ROADMAP.md`, `BUILD_APK.md` — техническая документация.
- `НАЧНИ_ОТСЮДА.md` — этот файл.

У тебя есть **три пути**. Начни с Пути А.

## ПУТЬ А. Просто увидеть приложение на своём телефоне (проще всего)

Здесь ничего не нужно устанавливать на компьютер. Приложение соберётся в
облаке (бесплатно), а ты скачаешь готовый файл `.apk` и поставишь на Android.
Это будет **демо-версия** — со встроенными примерами товаров, без регистрации.
То самое, что ты «щупал» в чате, только настоящим приложением на телефоне.

> Важно: iPhone так не получится — для него нужен компьютер Mac и платный
> аккаунт Apple. Дальше речь только про Android.

### Шаг 1. Аккаунт GitHub
1. Зайди на **github.com**, нажми **Sign up**, заведи бесплатный аккаунт
   (почта, пароль, подтверждение).

### Шаг 2. Загрузить проект в GitHub (через программу, без командной строки)
1. Скачай и установи **GitHub Desktop**: **desktop.github.com** → Download.
2. Запусти, войди своим аккаунтом GitHub.
3. Вверху меню: **File → Add local repository** → выбери папку проекта
   (`Приложение`).
4. Появится надпись, что это «не репозиторий» и предложение
   **«create a repository»** — нажми его, затем кнопку **Create repository**.
5. Нажми **Publish repository** (можно оставить галочку «Keep this code
   private» — приватно). Готово, код загрузился в облако GitHub.

### Шаг 3. Дождаться сборки и скачать APK
1. Открой свой репозиторий на сайте **github.com** (он появится в твоём
   профиле).
2. Вкладка **Actions** (вверху). Там сама запустится сборка «CI & Build APK».
   Подожди 5–10 минут, пока не появится зелёная галочка ✓.
3. Кликни на завершённую сборку → внизу страницы блок **Artifacts** → скачай
   **komplekt-apk** (это архив `.zip`).
4. Распакуй архив — внутри файл **`app-debug.apk`**.

### Шаг 4. Установить на телефон
1. Перекинь `app-debug.apk` на телефон удобным способом: отправь себе в
   Telegram («Избранное»), на почту, в Google Drive или по USB-кабелю.
2. На телефоне открой этот файл. Android попросит разрешить **«установку из
   неизвестных источников»** — разреши для этого приложения.
3. Нажми «Установить». Готово — приложение «КОМПЛЕКТ» на телефоне.

### Если сборка стала красной (✗) — это нормально
Код собирается впервые, поэтому первая попытка может «упасть» с ошибкой.
Это не страшно и легко чинится:
1. На вкладке **Actions** открой красную сборку.
2. Нажми на упавший шаг (обычно **Build debug APK** или **Analyze**).
3. Выдели и скопируй красный текст ошибок (или сделай скриншот).
4. **Пришли его мне** — я скажу, что поправить. Ты внесёшь правку (через
   GitHub Desktop: кнопка **Commit** → **Push**), и сборка повторится сама.

## ПУТЬ Б. Сделать «настоящую» версию (с регистрацией и сохранением данных)

Демо-версия из Пути А ничего не сохраняет. Чтобы появились реальная
регистрация, избранное, подборки, цены поставщиков — нужно подключить
бесплатное облако **Supabase** (это база данных и сервер). Сделать это можно
самому, копируя готовый текст — программировать не нужно.

### Шаг 1. Создать проект Supabase
1. Зайди на **supabase.com**, нажми **Start your project**, войди (можно через
   тот же GitHub).
2. **New project**: имя `komplekt`, придумай и **сохрани пароль базы данных**,
   регион выбери ближайший (например, Frankfurt). Нажми создать, подожди ~2 мин.

### Шаг 2. Создать таблицы (копировать-вставить)
1. В Supabase слева открой **SQL Editor** → **New query**.
2. На компьютере открой файл `supabase/migrations/0001_init.sql` обычным
   Блокнотом, выдели весь текст (Ctrl+A), скопируй (Ctrl+C), вставь в окно
   Supabase и нажми **Run**.
3. Повтори то же самое по очереди для остальных файлов из папки
   `supabase/migrations/`: **0002, 0003, 0004, 0005, 0006** — именно в этом
   порядке, каждый отдельным запросом.

### Шаг 3. Взять ключи доступа
1. В Supabase: значок шестерёнки **Project Settings** → **Data API** → скопируй
   **Project URL**.
2. Там же **API Keys** → скопируй ключ **anon / publishable**.

### Шаг 4. Прописать ключи в проект
1. В папке проекта найди файл `.env.example`, сделай его копию и переименуй
   копию в `.env` (просто `.env`, без `.example`).
2. Открой `.env` Блокнотом и впиши:
   - в строку `SUPABASE_URL=` — скопированный Project URL;
   - в строку `SUPABASE_ANON_KEY=` — скопированный ключ;
   - строку `DEMO_MODE=true` поменяй на `DEMO_MODE=false`.
3. Сохрани файл.

### Шаг 5. Включить вход по email
1. В Supabase: **Authentication → Providers → Email** — на время отладки
   выключи галочку **Confirm email** (чтобы регистрация сразу пускала внутрь).
2. Вход по **телефону/SMS** требует отдельного платного SMS-сервиса (Twilio) —
   это уже на потом; email работает сразу.

> Сборка APK из Пути А всегда делает **демо-версию** (так задумано, чтобы
> секретные ключи не утекли в открытый доступ). Чтобы собрать «боевую» версию с
> твоими ключами Supabase, приложение нужно собрать **на компьютере** (Путь В)
> или поручить это разработчику. Зато после шагов выше весь бэкенд уже готов —
> разработчику останется совсем немного.

## ПУТЬ В. Менять приложение самому (для самых смелых)

Если захочешь сам редактировать приложение и собирать его на компьютере, нужно
установить **Flutter** и **Android Studio**. Это уже посложнее, всё подробно
расписано в файле `README.md`, раздел «Запуск на Windows». Команда для сборки —
одна: `flutter build apk`. Но без базового знакомства с этим будет тяжеловато —
лучше делать вместе с тем, кто разбирается.

## Что честно пока нельзя сделать без помощи

- **Первая компиляция.** Код ещё ни разу не «собирался» компьютером, поэтому
  почти наверняка всплывёт несколько мелких ошибок. Их ловит Путь А (облачная
  сборка) — присылай ошибки мне, поправлю.
- **Пуш-уведомления** (о снижении цены) требуют отдельной настройки Firebase, а
  для iPhone — платного аккаунта Apple. Инструкция есть в `README.md`.
- **Публикация в Google Play / App Store** — нужны аккаунты разработчика
  (Google — $25 один раз, Apple — $99 в год), иконки, скриншоты, политика
  конфиденциальности. Это финальный этап.
- **iPhone-версия** — собирается только на компьютере Mac.

Полный список «что ещё доделать» — в файле `ROADMAP.md`.

## Как двигаться дальше (рекомендация)

1. Сначала **Путь А** — собери демо-APK, поставь на телефон, покажи знакомым,
   убедись, что идея нравится. Если сборка упадёт — пришли мне ошибку, починим.
2. Потом **Путь Б** — подключи Supabase, чтобы появилась настоящая регистрация
   и сохранение данных.
3. Для «боевой» сборки, пушей и публикации в магазинах — подключи разработчика
   (или меня для правок по коду). Большая часть фундамента уже готова.

Если что-то непонятно на любом шаге — просто опиши мне словами, что видишь на
экране, или пришли скриншот. Будем разбираться вместе.
